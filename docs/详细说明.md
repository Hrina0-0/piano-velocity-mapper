# 钢琴力度重映射工具

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Windows](https://img.shields.io/badge/Windows-10%20%2F%2011-0078D4?logo=windows)](https://learn.microsoft.com/zh-cn/windows/)
[![Python](https://img.shields.io/badge/Python-3.10--3.13-blue?logo=python)](https://www.python.org/)

把任何"力度打不满"的 MIDI 键盘发出的力度**实时**重映射到 1–127，经 loopMIDI
虚拟端口输出。Cubase / FL Studio（以及任何其他软件）把 MIDI 输入源切到
loopMIDI 即可，**所有 DAW 和音源统一生效**。

> 为什么需要：不少小尺寸键床的 MIDI 键盘（61 键、88 键重锤等）力度键数少，
> 无论怎么用力砸，实测最大只能到约 95–110，而音源支持到 127，导致弹奏整体偏轻。
> 本工具把 raw 的最大值抬到 127。

```
键盘 (USB-MIDI)  ->  app.py（GUI）+ engine.py  ->  loopMIDI Port  ->  宿主
```

## 功能特性

- **桌面图形界面**（v1.3 新增，默认入口）：双击桌面快捷方式即启动，
  无黑色命令行窗口；力度、曲线、端口、日志全部在窗口里操作
- 只改写 Note On 的力度；力度为 0 的 Note On 原样透传（MIDI 中它等价于 note-off）
- Note Off / CC（含延音踏板 CC64）/ 弯音 / 通道信息等一律原样透传
- 输入设备掉线后每 2 秒自动重连，先开宿主还是先开工具都行
- 所有状态提示防刷屏：相同内容不重复打印，同类提示至少间隔 3 秒；等待连接时只提示一次，之后静默自动重试
- `--monitor` 标定模式：边弹边打印「原始力度 -> 映射力度」，测出真实最大力度
- 可调力度曲线（线性 / 下凸 / 上凸），按手感微调
- 网页控制台保留可用（高级/远程调参场景），但日常使用不需要它

## 1. 系统要求

- Windows 10/11
- **Python 3.10 ~ 3.13**（未安装：https://www.python.org/downloads/ ，安装时勾选
  “Add Python to PATH”）
- loopMIDI（免费，作者 Tobias Erichsen）：
  https://www.tobias-erichsen.de/software/loopmidi.html

> **为什么不是“3.10+”**：MIDI 后端用的 pygame 目前没有发布 3.14 的 wheel，
> 3.14 上装不上依赖。所以 `setup.cmd` 会主动找 3.10–3.13，找不到就明确报错。
>
> **别删掉 Python**：`.venv` 只是“指向某个 Python 安装的快捷方式”。一旦那个
> Python 被卸载/清理，`.venv` 就变成一堆死文件，双击快捷方式会报
> “Python venv launcher is sorry to say … did not find executable”。
> 这时**重新双击 `setup.cmd` 就行**——它会发现环境失效并重建。
> （本项目不会替你装 Python，因为装 Python 属于改系统，得你自己确认。）
- loopMIDI（免费，作者 Tobias Erichsen）：
  https://www.tobias-erichsen.de/software/loopmidi.html

## 2. 安装 loopMIDI

1. 打开上面的链接下载并安装 loopMIDI
2. 打开 loopMIDI，在 Port Name 里输入 `loopMIDI Port`，点 **+** 创建虚拟端口
3. 让 loopMIDI 保持运行（最小化即可），点 **Start** 按钮使端口处于活动状态

> 如果端口名不是 `loopMIDI Port`，请把实际名字填进 `config.json` 的
> `output_port`。

### 其实不用你手动开 loopMIDI

工具启动时会自己做这几件事（见 `midi_ports.py`）：

1. 检查当前配置里的输出端口还在不在；
2. 不在了就找系统里其它虚拟端口（Bome / VMP / MIDI Yoke 等都行）；
3. 还没有，但你机器上装了 loopMIDI —— **自动把 loopMIDI 启动起来**，等端口出现后自动接上；
4. 确实找不到，才弹一个引导窗，告诉你去哪儿下载、怎么建端口。

窗口「端口」卡片下面那行提示会直接告诉你当前用的是不是虚拟端口：

- 绿色 `虚拟端口「loopMIDI Port」· DAW 里请选同一个` —— 对了
- 橙色 `是硬件端口，DAW 收不到重映射后的力度` —— 选错了，换一个

> **为什么工具不自带 loopMIDI？** 因为 Tobias Erichsen 明确要求「未经书面同意
> 不得以任何方式分发」他的软件。工具只负责**启动你自己装的那一份**，不夹带二进制。

## 3. 安装与首次启动

### 推荐：桌面图形界面（日常就用这个）

| 文件 | 作用 |
| --- | --- |
| `setup.cmd` | **只跑一次**：建 `.venv`、装依赖、在桌面创建快捷方式 |
| 桌面「钢琴力度重映射」 | 日常启动。无命令行窗口，所有功能在窗口里 |

> 它同时也是自愈的：环境坏了、Python 被删了、版本太新了，都会自动重建并给出
> 对应的处理提示。

### 备选：两个命令行入口

| 文件 | 作用 |
| --- | --- |
| `start_mapper.bat` | **转发模式**（命令行版，弹黑框）：弹琴 → 映射力度 → 转发到 loopMIDI → 宿主 |
| `calibrate.bat` | **标定模式**：只显示力度、不转发，用于测出真实最大力度 |

**标定真实最大力度**：桌面窗口里弹几下，「实时力度」区会直接给出
**「建议最大力度 N」**，点旁边的 **「采用 N」** 即可；也可以双击 `calibrate.bat`
用最重的手法砸琴，工具会实时显示累计 `raw` 范围和映射后范围。
把建议值填进 `config.json` 的 `max_input_velocity`，保存后砸到底就是 127。

> 说明：映射是把「raw 的最大值」抬到 127。本机实测最重砸到 **75–83**，
> 所以 `max_input_velocity` 填 75（`config.json` 里的初始值）——
> 设得比真实最大值小，最重几档会糊在 127 上失去层次；设得比它大，
> 最重也够不到 127。用「采用建议值」最省事。

正常转发：

```bat
start_mapper.bat
```

或手动运行：

```bat
.venv\Scripts\python.exe velocity_mapper.py
```

常用参数：

| 参数 | 作用 |
| --- | --- |
| `--monitor` | 标定模式：只打印 raw -> mapped，不转发 |
| `--list` | 仅列出 MIDI 输入/输出端口后退出 |
| `--verbose` | 转发模式下逐音符打印力度映射 |
| `--config <路径>` | 指定配置文件（默认同目录 config.json） |
| `--no-web` | 不启动网页控制台（纯命令行转发，不自动开浏览器） |

> 转发模式（`start_mapper.bat`）只在一个位置**原地刷新**显示"最近一次映射后的力度"，
> 不滚动刷日志；要看每个音符的原始/映射明细，加 `--verbose`；标定看完整日志用 `calibrate.bat`。

## 4. 桌面窗口里能干什么

启动后一个窗口，所有日常操作都在里面完成：

| 区域 | 说明 |
| --- | --- |
| **顶部状态药丸** | `已连接` / `端口被占用` / `未找到端口`，一眼看出链路状态 |
| **力度映射 · 最大力度** | 对应 `max_input_velocity`，拖动即时改变“砸到底 = 127”的位置 |
| **力度映射 · 力度曲线** | 对应 `curve_exponent`，**步长 0.1**（0.2 ~ 3.0），线性 / 柔和 / 爆发三挡快捷预设 |
| **实时力度** | 弹一下就显示 `原始 → 映射` 的大数字 + 音名 + 两条力度条 |
| **实时力度 · 建议最大力度** | 弹一会儿后出现 `建议最大力度 N`，点 **「采用 N」** 一键套用 |
| **力度曲线图** | 蓝线 = 当前映射，网格标出 32/64/96/127 对应的原始力度 |
| **端口** | 输入（键盘）/ 输出（loopMIDI）下拉切换，改完自动重连；「刷新端口」重新扫描 |
| **运行日志** | 连接、掉线、端口占用、参数改动都在这里，带时间戳 |

所有改动都会自动写回 `config.json`（右下角会闪一下「已保存」），下次启动仍然有效。
力度/曲线拖动**不会**触发重连，只有换端口才会。

### 关窗口时：退出还是留在后台？

点右上角 ✕（或按 Esc）会弹一个小对话框，问「要完全退出这个工具吗？」：

| 选项 | 行为 |
| --- | --- |
| **是 · 完全退出** | 真正结束进程，端口释放，任务栏里不再有它 |
| **否 · 留在后台运行** | 窗口隐藏，**托盘图标常驻**，力度转发继续跑；左键点托盘图标就能把窗口叫回来 |
| **下次不再提示** | 勾上以后记住这次的选择（存在 `ui_prefs.json`），以后点 ✕ 直接执行，不再询问 |

点标题栏的 **最小化** 按钮也会收进托盘（同样可以在托盘菜单里关掉这个行为）。

托盘图标（任务栏右下角通知区域，可能藏在 `^` 展开的溢出区里）：

| 操作 | 行为 |
| --- | --- |
| **左键单击** | 把主窗口叫回前台 |
| **右键菜单** | 显示主窗口 / 最小化到后台 / ─ / 关闭时总是询问 / 最小化时收进托盘 / ─ / 完全退出 |
| **「关闭时总是询问」** | 取消「下次不再提示」，恢复每次点 ✕ 都询问 |

已经在后台跑着的时候**再点一次桌面快捷方式**，不会开第二个实例，而是把后台那个的窗口叫回前台。

### 图形细节

曲线、落点圆圈、滑块手柄都是**抗锯齿**绘制的（借 pygame 在高分辨率下画好再
缩放贴回 Tk），所以不会出现锯齿边；整个界面空闲时几乎不占 CPU。

### 网页控制台（可选，仍可用）

不想开图形界面时，双击 `start_mapper.bat` 会在浏览器里打开网页控制台
（`http://127.0.0.1:8765`，只在本机有效），功能与窗口一致，适合远程/多屏调参。
日常使用不需要它。

**连着宿主也能边弹边调**：宿主只监听 loopMIDI 就好，不要在宿主里直接开
键盘的输入（否则钢琴口会被宿主占用，窗口顶部会显示“端口被占用”）。

## 5. 配置说明（config.json）

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `input_port_substring` | `Digital Piano` | 输入端口名包含该子串即匹配；可用 `--list` 查看实际设备名 |
| `output_port` | `loopMIDI Port` | 输出端口名（loopMIDI 里创建的端口名） |
| `max_input_velocity` | `75` | 你的键盘实际能达到的最大力度（窗口里弹几下点「采用建议值」即可） |
| `curve_exponent` | `1.0` | 力度曲线指数：`1.0` 线性；`>1` 高力度段更陡（轻弹更轻）；`<1` 低力度段更陡 |
| `log_interval_sec` | `2.0` | 心跳日志间隔（秒） |

映射公式：`v' = 1 + 126 * ((v - 1) / (max_in - 1)) ^ exp`，四舍五入并截断到 1–127。

## 6. 宿主接线

### FL Studio

1. 打开 `Options > MIDI settings`（快捷键 F10）
2. 在 **Input** 列表里选中 `loopMIDI Port`，点击 **Enable**
3. **停用** 键盘的直连输入（取消 Enable），避免同一个音符弹两遍（双音符）
4. 直接弹奏，力度即已重映射

> 提示：F10 里的 “Link note on velocity to” 保持默认 `Velocity` 即可，
> 力度映射已在本工具内完成，不要再用 FL 的 Curve 二次映射。

### Cubase

1. `Studio > Studio Setup > MIDI Ports`
2. 把 **loopMIDI Port** 的 **In** 激活（点亮）
3. 在 MIDI/乐器轨的 Inspector 里，把轨道的 MIDI **Input** 选为 `loopMIDI Port`
   （而不是键盘直连）
4. 弹奏验证；若仍有双音符，说明键盘直连输入仍在某条轨道上，改掉即可

> 注意：Cubase 的 MIDI Modifiers 不要再叠加力度压缩，避免双重映射。

## 7. 日常使用

- 每次弹奏前：打开 loopMIDI（保持 Start 状态），再双击桌面上的
  **「钢琴力度重映射」**
- 不想开图形界面：双击 `start_mapper.bat`（转发模式）/ `calibrate.bat`（标定）
- 想开机自启：把桌面快捷方式放进 `shell:startup` 文件夹即可（可选）
- 换手感：拖「最大力度 / 力度曲线」滑块，立即生效并自动保存；
  或弹几下点「采用建议值」
- 工具同一时间只允许运行一个实例：重复双击会提示“已经有一个实例在运行”，
  关掉旧窗口后再开即可

## 9. 故障排查

| 现象 | 处理 |
| --- | --- |
| 顶部显示“端口被占用” | 工具其实已经在运行，或其它软件占着键盘端口。关掉多余的工具窗口（或到任务管理器结束旧进程）、在宿主里停用键盘直连；工具会每 2 秒自动重试，不用重启 |
| 提示“未找到输出端口” | loopMIDI 没安装/没打开/没创建端口；核对端口下拉里的实际名字。该提示只出现一次，工具会每 2 秒自动重试，打开 loopMIDI 后无需重启工具 |
| 提示“未找到输入端口” | 键盘没连接或驱动异常；在「端口」里点「刷新端口」看实际设备名，再重新选 |
| 提示“输入和输出选了同一个端口” | 两边选成了同一个虚拟端口，音符会自我回环。输入选电钢琴的 USB 端口，输出选 loopMIDI 端口 |
| 弹奏出现双音符 | 宿主里还开着键盘直连输入，停用即可 |
| 轻弹也偏响 | 把「力度曲线」往「爆发」方向拖，或用 `--monitor` 看实际分布 |
| 延迟 | Windows 后端约 1–3ms 额外延迟属正常；若无法接受，可改用 Bome MIDI Translator Classic 配置同一映射 |
| 双击快捷方式没反应 | 先双击 `setup.cmd` 完成一次安装（或重跑一次，环境坏了会自动重建） |
| 弹出 “Python venv launcher is sorry to say … did not find executable” | 你删掉了当初建 `.venv` 时用的那个 Python。装一个 3.13，然后重双击 `setup.cmd` |
| 弹出 “没有找到 Python 3.10 - 3.13” | 只有 3.14 或没装。装一个 3.13（pygame 暂无 3.14 版本），装完重跑 `setup.cmd` |
| 弹不出黑框但窗口一闪就没 | 多半是没找到 MIDI 后端；双击 `setup.cmd` 重装依赖，或直接跑 `.venv\Scripts\python.exe app.py` 看报错 |
| 网页打不开（用命令行模式时） | 确认工具窗口还开着；端口被占用时工具会自动换一个端口，以控制台显示的地址为准 |

## 11. 打包分发（给别人用）

git tag v1.0.0 && git push origin v1.0.0
```

本地打包（不想用 CI 时）：

powershell -ExecutionPolicy Bypass -File make_release.ps1 -Version 1.3.0
```

| 包 | 内容 | 对方要做什么 |

| `PianoVelocityMapper-v1.3.0.zip` | 单个 `PianoVelocityMapper.exe`（≈18 MB）+ 使用说明 | 解压双击即用，不用装 Python |

源码就在本仓库里（MIT 许可），对方想改代码直接 clone 或用 *Code → Download ZIP*。

这个包**不含任何第三方软件**：loopMIDI 需要对方自己从官网装一次，装完之后
工具会自动帮你启动它，以后只需要开这一个软件。

打包相关的文件：

| 文件 | 作用 |
| --- | --- |
| `build_exe.py` | 单独打单文件 exe（PyInstaller） |
| `make_release.ps1` | 组装分发包 |
| `paths.py` | 区分只读资源目录 / 可写数据目录（打包后配置要写在 exe 旁边） |
| `check_ports.py` | 环境体检，`setup.cmd` 末尾会调用 |

> 打包的是 `--onefile`，启动时会把依赖解到临时目录再跑，所以第一次启动会
> 慢一两秒，属正常。
